# Аудит шахматки квартир

## Фактическая модель

Шахматка — это список `этаж → загруженные квартиры`, а не матрица `корпус → секция → этаж → позиция`. Код строит строки только из `floor` (`src/main.ts:398-418`). Это корректно обозначено предупреждением, но визуальный термин «шахматка» создаёт ожидание полноценной топологии.

## Данные

- 188 квартир / 18 ЖК.
- `id` и `xmlId` уникальны.
- 188/188: `building = null`, `section = null`.
- Единственный статус: `свободна`; «бронь/продана/недоступна» проверить невозможно.
- Один повтор номера внутри проекта: JAŃA QALA №22 (этажи 7 и 3). Это не дубликат `id`, но риск неверной коммуникации с продажами.
- Цена, этаж и планировка заполнены у всех 188; соотношение `price / area` к `priceM2` не расходится более чем на 1%.

## Проблемы

### CHESS-001 — P1 — неполный каталог выглядит как структура дома

JAŃA QALA показывает 12 из 91, Aibat 18 из 257 и т. п. Пустая строка «—» может быть прочитана как отсутствие квартир, хотя данные просто не загружены.

**Решение:** до официальной выгрузки заменить пустое значение на «данных нет», добавить coverage badge и запретить агрегат «свободных» как полный. **Приёмка:** пользователь различает «0 свободных» и «нет данных» текстом, не только цветом.

### CHESS-002 — P1 — отсутствуют корпус и секция

Нельзя подтвердить этажность конкретного корпуса или соседство квартир.

**Решение:** контракт данных `buildingId`, `sectionId`, `floorId`, `unitPosition`, `statusUpdatedAt`; импорт из CRM/шахматки застройщика с валидацией ссылочной целостности.

### CHESS-003 — P2 — визуальные статусы неполны

Есть только зелёная «свободна» и orange selected. Нет текста статуса в самой ячейке, фильтр-match/dim, бронь/продана/недоступна.

**Решение:** цвет + короткий label/icon; легенда; `aria-label` с №, этажом, статусом, площадью и ценой.

### CHESS-004 — P2 — номер квартиры скрыт

Номер находится только в `title`; на touch он практически недоступен. Ячейка показывает комнатность + цену.

**Решение:** основной ряд `№15 · 1К`, второй `44 м²`, третий `38,2 млн`; цена/площадь переключаемы для плотного режима.

## Оптимальный UX для больших домов

1. Sticky selectors: корпус, секция, диапазон этажей.
2. Виртуализированный grid; sticky номера этажей и секций.
3. Режимы «матрица» и «список»; список обязателен для accessibility.
4. Фильтры визуально приглушают несовпадения, но не меняют позицию ячеек.
5. Клик сохраняет `apartmentId` и синхронно подсвечивает корректную геометрию.
6. Возврат восстанавливает scroll, zoom и фильтры.

## Приёмочные тесты

- Ни один `apartmentId` не повторяется; номер уникален в пределах секции или явно составной.
- Количество квартир по этажу совпадает с официальной выгрузкой.
- Все статусы имеют текстовый эквивалент.
- 1 000+ ячеек скроллятся без long task >200 мс на целевом устройстве.
- На 320 px выбранная квартира видна и открывается одной рукой.
