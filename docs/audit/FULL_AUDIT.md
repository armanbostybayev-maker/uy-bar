# Комплексный аудит SvoyDom3D

Дата проверки: 20.11.2026. Объект: `C:\SvoyDom3D`, `http://localhost:5178/`.

## Резюме

Текущая версия — честно маркированный концепт 3D-карты, а не готовая платформа покупки. Она успешно показывает 81 ЖК, фильтрует карту, открывает карточку ЖК, ограниченную шахматку, карточку квартиры и ориентировочный аннуитетный расчёт. Основной путь «ЖК → этаж → квартира → цена → ипотека» демонстрируется, но путь «город/район → дом → корпус → секция → точная квартира → заявка» отсутствует или недостоверно воспроизводим из-за неполных исходных данных.

Главный вывод: демонстрацию можно использовать для обсуждения продукта, но нельзя выпускать как сервис выбора квартиры. Критические блокеры — отсутствие подтверждённой связи квартиры с корпусом/секцией/геометрией, неполные каталоги, отсутствие production-заявки и недостаточная валидация ипотечного калькулятора.

## Проверено

- Изучены README, маршруты, данные, `src/main.ts`, `src/mortgage.ts`, `src/data.ts`, `src/geo.ts`, стили и build pipeline.
- Production-сборка `npm run build` успешна: 81 проект; 41 OSM-геометрия, 40 схематичных, ручных override — 0.
- Практически открыты карта, JAŃA QALA, шахматка, квартира №15, мобильный bottom sheet и ипотечный блок.
- Проверены контрольные ширины 320, 360, 375, 390, 414, 430, 768, 1024, 1280, 1440 и 1920 px (ограничение стенда: фактический встроенный viewport выше 1280 px не всегда применялся).
- Данные: 188 квартир, 18 ЖК, уникальные `id`/`xmlId`, все 188 без корпуса и секции; один повтор пользовательского номера внутри ЖК — `janaqala`, №22 на разных этажах.
- Консольных ошибок в проверенном сценарии не обнаружено.

Не выполнено: физические iOS/Android, screen reader, сетевое throttling, Lighthouse/INP/LCP/CLS на 75-м процентиле, production CRM и реальные банковские API. Эти проверки не засчитаны как успешные.

| Сравнить квартиры | Не поддерживается | — | Нет избранного/сравнения |
| Рассчитать ипотеку | Частично | 5–7 | Только аннуитет, нет полной детализации и строгой валидации |

## Подтверждённые проблемы верхнего уровня

1. **AUD-DATA-001 / P0:** нельзя достоверно показать выбранную квартиру в конкретном корпусе/секции/на фасаде. `src/main.ts:328-345` применяет этаж ко всем зданиям; `src/main.ts:444-447` прямо сообщает об отсутствии данных.
2. **AUD-DATA-002 / P1:** 188/188 квартир не имеют корпуса и секции; для большинства ЖК загружено 12–18 записей вместо полного каталога (`src/main.ts:351-355`).
3. **AUD-CONV-001 / P1:** кнопка «Оставить заявку» только показывает toast и не создаёт заявку (`src/main.ts:451-457`). Для демо это честно, для продукта — блокер.
4. **AUD-MORT-001 / P1:** входы ограничены только HTML-атрибутами; модель принимает отрицательные/нулевые/нечисловые пограничные значения без единой схемы ошибок (`src/mortgage.ts:10-13,27-39`).
5. **AUD-NAV-001 / P1:** URL сохраняет только slug ЖК; квартира, вкладка, этаж, фильтры и камера не восстанавливаются (`src/main.ts:286-309,508-510,564-567`).
6. **AUD-A11Y-001 / P1:** карта и 3D-этажи не имеют клавиатурной/списочной альтернативы; основной выбор зависит от canvas.
7. **AUD-CHESS-001 / P2:** ячейка показывает только комнатность и цену, без номера/площади/статуса текстом; на мобильном сравнение соседних квартир затруднено (`src/main.ts:403-410`).
8. **AUD-DATA-003 / P2:** внутри JAŃA QALA номер №22 встречается дважды на этажах 7 и 3; `id` уникальны, но пользовательская идентификация неоднозначна.

## Архитектура и безопасность

Сильные стороны: внешний текст экранируется через `esc`, ссылки используют `rel="noopener"`, нет клиентских секретов, данные и дисклеймер отделяют демо от официального сайта. Риски: `tooltip`/`toast` используют `innerHTML`; текущие значения экранированы, но эту границу легко нарушить при развитии. Нет CSP, SRI и backend-валидации (backend отсутствует). Персональные данные не собираются, поэтому согласие пока не требуется; при реализации заявки оно обязательно.
