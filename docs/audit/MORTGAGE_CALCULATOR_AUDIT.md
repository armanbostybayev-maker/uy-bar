# Аудит ипотечного калькулятора

## Проверенная формула

`monthly()` в `src/mortgage.ts:10-13` реализует стандартный аннуитет: `P*r/(1-(1+r)^-n)` и отдельную ветку 0%. Для квартиры 38 236 000 ₸, взноса 20%, 7% и 25 лет интерфейс показывает 216 195 ₸/мес.; независимый расчёт совпадает после округления.

## Матрица обязательных тестов

| Тест | Результат |
|---|---|
| Взнос 0/10/20/50% | Формула способна посчитать, UI принимает 0–90 |
| Взнос 100% | **Не поддерживается:** `max=90` |
| Ставка 0% | Формула предусмотрена |
| Минимальный/максимальный срок | UI 1–30 лет; бизнес-правила программы не проверяются |
| Цена 0/отрицательная | Widget не показывается при falsy цене; отдельной ошибки нет |
| Отрицательные значения | Только HTML min/max, модель не clamp/validate |
| Большие суммы | Нет лимита/overflow policy |
| Текстовый ввод | `Number(value) || 0`, ошибка превращается в 0 без сообщения |
| Тенге/% для взноса | Только проценты |
| Тип платежа | Только аннуитет |
| Сброс | Только выбор preset; общей кнопки нет |
| Детализация/график | Нет |

## Проблемы

### MORT-001 — P1 — нет доменной валидации

Атрибуты `min/max` не защищают функцию или программное значение. `years=0` при нулевой ставке даёт деление на ноль; отрицательный срок/ставка могут дать бессмысленный платёж.

**Решение:** чистая функция `calculateMortgage(input): Result<Breakdown, ValidationError[]>`; Decimal/целые тиыны; проверки `price>=0`, `0<=down<=price`, `0<=rate`, `months>=1`.

### MORT-002 — P1 — preset «7-20-25» не проверяет применимость

Отсутствуют дата актуальности, источник, лимит стоимости, требования к объекту и заёмщику, ГЭСВ. Дисклеймер снижает риск, но название программы создаёт ожидание eligibility.

**Решение:** либо «пример 7/20/25», либо серверный каталог программ с `sourceUrl`, `validFrom/To`, limits и eligibility message.

### MORT-003 — P2 — неполная финансовая картина

Нет общей выплаты, процентов, переплаты, комиссий, графика и остатка.

**Решение:** амортизационный schedule с последним платежом, корректирующим остаток до 0; суммы округлять единообразно до тенге только для отображения.

## Рекомендуемые unit-тесты

- Golden cases для 0%, 7%, 18.5%, 1/12/360 месяцев.
- Property tests: платёж неотрицателен; больший взнос не увеличивает платёж; при 0% сумма платежей = principal.
- 100% взнос → loan/payment/interest = 0.
- Некорректный ввод возвращает ошибку, а не молча 0.
- Последний остаток ровно 0, переплата = total - principal.

## Критерии приёмки

Пользователь видит цену, взнос в ₸ и %, сумму кредита, платёж, переплату и источник условий; смена квартиры пересчитывает всё без старой цены; все обязательные edge cases покрыты unit-тестами.
